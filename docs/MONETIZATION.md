## 1. 과금 체계 (2026-11-16 대표 결정 "다 추천대로")
2026-11-08 결정 "무료 체험 7일(Apple 체험) → 월 3,000원"을 아래로 바꾼다.

### P1 = (A) 가입 후 14일 무료, 카드 없이, Apple 체험 없음
- 가입한 순간 서버가 `trial_ends_at = 가입 시각 + 14일`을 저장한다. 카드 등록·결제 창 없음.
- 14일이 지나면 바로 구독(월 3,000원). App Store 구독 상품에 introductory offer(무료 체험)를 **설정하지 않는다** — 붙이면 2주 + 7일 = 3주가 된다.
- 이유: 마당(기록한 날 누적 7일)·추억 나무 1단계(10일)를 결제 판단 전에 겪게 함 / 모두가 같은 날 결제벽을 만나지 않음 / 출시 행사가 아니라 계속 쓰는 구조 / 14세 이상 학생은 카드가 없는 경우가 많음 / 가입 주차별 "14일째 결제율"이 깨끗하게 나옴.
- 대가: 카드 없는 체험은 카드 받는 체험보다 전환율이 낮은 편(대신 시작하는 사람이 많음), 첫 매출이 사람마다 7일 늦음.
- 새 계정으로 14일을 다시 받는 것은 막지 않는다(기록·단짝이 처음부터라 남용 적음).
- 버린 안: (B) 기존 7일 체험, (C) 출시일부터 모두 같은 날짜까지 무료 + 7일 체험.

### P2 = (A) 구독이 없으면 '새 기록 쓰기'만 잠근다
- 잠김: 새 기록 저장(그래서 기록으로 받는 씨앗·텃밭 성장·기록한 날 수도 자연히 멈춤).
- 계속 무료: 앱 열기, 방·단짝·텃밭·마당 보기, **이미 가진 씨앗으로 상점·심기**, 수확물 먹이기, 지난 기록 보기·찾기·☆·메모 보기, 내보내기, 삭제, 안전 안내(설정 › 도움받을 수 있는 곳). 이미 얻은 것은 아무것도 사라지지 않는다(잃는 장치 금지).
- 결제벽 위치: 앱을 열 때 막지 않는다. 입력 알약을 누르면 그때 구독 시트.
- 버린 안: (B) 기록은 무료, 꾸미기만 잠금 — 핵심 가치가 공짜라 매출이 약함.

### P3 = (A) 알림은 두 번, 날짜로
- 가입할 때(온보딩 끝): "가입 후 2주 동안 무료야. ○월 ○일까지." 한 번.
- 끝나기 2일 전: 날짜로 한 번(기기 안 예약 알림 — 처리방침상 알림은 서버로 안 보냄). "N일 남음" 같은 카운트다운 문구 금지, 설정 화면에는 "○월 ○일까지 무료"를 조용히 표시.
- 자동 결제가 없으므로 유료 전환 동의(전자상거래법 21조의2) 화면은 필요 없다. 구독 화면에는 금액·자동 갱신·해지 방법·청약철회 제한 표시.

## 3. 개발 스레드 할 일 (사업자등록·결제 연동 때, LAUNCH 4장)
1. 마이그레이션: `profiles.trial_ends_at timestamptz not null default now() + interval '14 days'` (기존 계정은 created_at + 14일, `testers`는 권한 제한 제외). 사용자가 바꿀 수 없는 서버 칸(RLS PATCH 금지).
2. 구독 상태: RevenueCat 웹훅 → Edge Function → `subscriptions`(user_id, product, expires_at, status) — 서버 칸.
3. 권한 함수 `has_access(uid)` = `now() < trial_ends_at` 또는 구독 유효. `record_win`이 확인해서 없으면 `subscription_required` 오류 (앱 화면만 막으면 우회됨). 씨앗 쓰기·심기·먹이기는 막지 않음.
4. 앱: 입력 알약 탭 시 권한 없으면 구독 시트(월【/연】, 구매 복원, 금액·자동 갱신·해지 방법·청약철회 제한), 설정에 "○월 ○일까지 무료"/구독 상태, 가입 직후 안내 1회, 끝나기 2일 전 기기 알림 1회.
5. App Store Connect: 구독 그룹 1개, 상품에 무료 체험 없음, Billing Grace Period 켜기. 구독 시트는 RevenueCat offerings를 읽어 그려서, 상품 추가·가격 변경에 앱 업데이트가 필요 없게.
6. 지표(`scripts/metrics.py`): 가입 주차별 14일째 결제율, 무료 기간 중 기록한 날 수 vs 결제 여부.

## 4. 연간 요금제 (대표 확인 대기 — 2026-11-16 제안)
2026-11-08엔 "연간은 재방문·유지 확인 뒤 추가"였다. 대표 질문: 매달 돈 나가는 게 싫은 사람에게 1년 결제가 더 편하지 않을까.
- Y1 출시 때 넣을지: (A) 출시 때 넣기 ← 추천 / (B) 원래대로 데이터 본 뒤
  - 넣는 이유: 매달 결제 알림이 싫은 사람에게 실제로 편한 선택지 / 14일을 써 본 뒤 고르는 거라 모르고 크게 결제하는 경우가 적음 / 개발 비용 거의 없음(같은 구독 그룹에 상품 1개, 전환은 Apple이 처리) / 선결제 현금·이탈 적음.
  - 위험: 환불 노출이 12배 — 공정위 '구독 = 계속거래(중도해지 환급)' 입장, 18조 11항 연대책임(LAUNCH 2장 기존 전문가 확인 항목)이 연간에서 더 커짐 / 학생에게 2만 원대 한 번은 부담(월 요금제가 그대로 있으니 문제는 아님) / 월 유지율 지표가 연간 결제자만큼 흐려짐(연간 결제자는 앱 안 기록한 날로 따로 봄).

# 첫 실행 순서 — 가입을 첫 기록 축하 뒤로 (2026-11-17, '첫 화면' 스레드)

계기: Chris Raroque 릴스 — 가입 → 온보딩을 온보딩 → 가입으로 바꾸니 가입률 약 40% 상대 상승(본인 앱 1개 수치).

## 대표 결정 (2026-11-17)
- O1 = A: 가입은 **첫 기록 축하 직후**. 순서: ① 인사(시작하기 / 이미 계정이 있어요) → ② 이름 → ③ 동의 → ④ 첫 기록 → ⑤ 축하 + 씨앗 → ⑥ 저장하기 = 가입 → ⑦ 방(선물 씨앗 6개 + 14일 무료 안내)
- O2 = B: 축하 직후 **바로 필수**, "나중에" 없음. 가입 안 하고 앱을 닫으면 다음 실행 때 ⑥으로 돌아옴(첫 기록은 남아 있음)
- O3 = B: 14일 무료는 **가입한 때부터** (지금 약관 문구 그대로). O2-B라 첫 실행~가입 사이가 몇 분이라 구멍 없음
- O4 = A: 첫 실행 단계별 이벤트를 출시 때 넣음 (아래 목록)

## 동의 위치
③ 동의는 첫 기록보다 앞. 기록 본문이 AI 분류(OpenAI, 미국)로 가기 때문. 출시 전 민감정보 별도 항목 추가(STATUS 11-13 결정)는 그대로 진행.

## O4 이벤트 (가입 전 단계도 세야 의미가 있음)
`ob_start`(① 표시) → `ob_name_done`(skip 여부) → `ob_consent_done` → `ob_first_win`(분류) → `ob_signup_shown` → `signed_in`(method, 기존) → `onboarding_done`(기존).
- 지금 `track()`은 로그인한 사용자만 저장(`lib/analytics.ts`). 가입 전 이탈을 보려면 O5-A(익명 계정)면 그대로 저장되고, O5-B면 무작위 설치 ID로 쓰는 별도 익명 이벤트 표가 필요.
- 볼 숫자: ①을 본 사람 중 ⑥까지 간 비율, ⑥을 본 사람 중 가입한 비율.

## 결정 필요
- O5 가입 전 데이터 보관 방식
  - (A) Supabase 익명 계정 ← 추천: 첫 기록도 지금과 똑같이 AI 분류 + 자해·위해 감지 2중 확인, 이벤트도 그대로. 대신 만들 것: 가입 안 한 익명 계정 7일 뒤 자동 삭제(+처리방침 한 줄), 익명 계정 남발 막기(IP 기준 분류 한도), 이미 가입한 계정으로 로그인하면 첫 기록을 그 계정으로 옮기는 서버 함수, 네이티브 Apple 로그인 연결 시험
  - (B) 폰에만 잠깐 보관 → 가입 때 올림: 서버에 가입 전 데이터 없음, 계정 충돌 없음. 대신 첫 기록의 AI 감지가 가입 뒤로 밀려 키워드 감지만으로 축하가 나감(감지 못 한 자해 표현을 축하할 위험), 이벤트용 익명 표 따로
